# WorkflowKit 1.10.0

新增五個輕量 BMAD 入口：`$wk-goal`、`$wk-plan`、`$wk-build`、`$wk-verify`、`$wk-project`。`$wk-goal` 同時作為智慧總入口；「開始明確變更」「繼續既有工作」「查看進度與下一步」三個常用操作共用同一份能力登錄表。各階段只讀取選定流程所需的完整 Skill 與 reference，保留 BMAD 6.12.4 的原生 renderer、runner 及階段依賴；Codex 自動提供的技能簡介仍由 Codex 管理。

一般 Build 維持預設。Build Auto 須由使用者明確選擇，並由 App Server 核對同步子代理及真實 sandbox 的 `git add`／`git commit` 能力。原生 Auto 狀態、完成與續作判讀已補齊。GitLab 綁定任務可先保留本機 Commit，遠端開 Issue、Push、Draft MR、Wiki 與報告發布仍由 Host 綁定實際成果取得人工確認。

Codebase Wiki 支援從固定來源直接探索功能，再交由 BMAD 整理需求及 Issue 草稿；不要求先建立 Wiki。共用 Group／Repository 參考明確區分安裝根、來源 Repo、執行目錄與成果目錄，讓受管理任務沿原 Group／Repo 保存文件索引及進度。Reviewer 的本機 runtime、共享快取與固定 request 保持獨立；各內含工具的實際 payload 由本版 source snapshot 摘要固定。

Codebase Wiki、MergeReviewer、ReleaseReviewer 沿用其 native 版本標籤，包含本輪已凍結的套件內修正；這三份來源在 `source-snapshots.json` 如實記為 `local-snapshot`／`dirty: true`，與相同版本的上游正式 ZIP 並非相同位元組。它們的已提交檔案、archive／tree digest 及 build pins 共同固定實際內容，不以 native 版本字串單獨判定身分。CommitReviewer 保持原正式附件。新工作台管理入口需搭配 GitLab Workspace 0.51.0，既有 installer／status API 及 0.49.0 最低安裝契約保持。

bundled 與 external BMAD 仍依原交易安裝、轉換及 rollback。external 原件保留，由工作台逐項偵測實際能力後啟用入口；本版不覆寫外部安裝，也不將未知外部能力標成已驗證。Output Style 保持明確載入。

補齊正式 1.9.0 的 Group／Repository、bundled／external 四種精確前版身分。先前登錄只有相同版本的早期候選，升到 1.10.0 後會拒絕正式 1.9.0；現在依已驗證的正式附件加入檔案與 profile 摘要，保留原候選識別及 rollback，修改過的未知內容仍不放行。

四個 GitLab 工作流程的主路徑已取得專用測試專案的實機證據，雙 Reviewer 報告已經人工確認、Host 發布、完整正文回讀及封存。完整故障與平台矩陣尚未全數完成；Wiki 更新衝突、多 Issue 部分成功／逾時、CLI／Chat 手動實跑等仍須後續驗證。既有未知任務及失敗收據保留。驗證範圍詳見[整合驗證紀錄](../validation/workflow-integration-20261114.md)。
